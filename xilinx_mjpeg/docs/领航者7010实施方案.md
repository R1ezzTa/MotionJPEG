# 领航者 7010：纯 FPGA 图像前端与 Ubuntu 展示

用户已确认只有领航者 7010。当前目标器件按本地规格书设为 `xc7z010clg400-1`，只使用 PL 完成图像数据通路，Ubuntu 负责接收、解码、显示、录像和可选识别。之前的 7020 推荐属于板卡比较结论，不再作为当前实施前提。

## 适合先做的版本

建议先实现单路彩色 JPEG 的完整链路：

```mermaid
flowchart LR
    C[一台 DVP 相机 / 片内图样] --> F[采集与跨时钟 FIFO]
    F --> A[亮度预处理]
    A --> J[一份自研 JPEG 核心]
    J --> Q[小容量片内 FIFO 与分包]
    Q --> N[PL MAC / RGMII / 千兆 PHY]
    N --> U[Ubuntu 重组与 JPEG 解码]
    U --> V[显示 / 录像 / 对照与统计]
```

联调从 640×480、30 fps 开始；若相机支持，再以 1280×720、30 fps 作为首版候选目标。它们是建议的阶段性配置，尚未经上板验证，用户也尚未确认要替代原方案的最终性能指标。JPEG 核心先按 100 MHz 内部时钟评估；RGMII 的千兆发送时钟为 125 MHz，两个时钟域之间使用异步 FIFO，不能将编码时钟直接当作网口发送时钟。

相机型号待确认。没有相机时可先用片内彩条、渐变或移动方块演示；测试源要按设定帧周期和有效像素速率输出，分别统计生成、编码和接收帧数。测试源支持反压不等于真实相机采集能力。

## 原双路方案在 7010 上的限制

7010 共有 17,600 LUT、35,200 FF、60 个 36 Kbit BRAM Tile、80 DSP48E1。之前双路模块在 7020 上使用 20,805 LUT、84 DSP，这份具体映射已超过 7010 的 LUT 与 DSP 容量。不同目标器件和优化约束会改变映射，不能将这些数字当作一次已完成的 7010 双路综合；但它们足以说明当前两份完整编码器不能直接作为可靠实施基线。

降低分辨率主要减少工作量与行缓存，不会自动消除两份 DCT、量化、熵编码等逻辑。如果以后必须使用 7010 实现双路，应重新设计共享编码器、输入调度和通道状态，或研究减少每份核心的资源。不能把两个相机逐像素接到一个普通编码器就称为双路共享：当前单路帧状态不能在帧中随意切换，无 PS DDR 时也没有两路完整原始帧缓存。

以较低分辨率逐帧轮流服务两台相机可以作为研究方向，但仍需第二路接线、相机同步或选帧、原始输入缓存及坏帧处理。单纯复用编码器并不保证双路持续无丢帧，更不保证原双路各 1080p60；后者需要显著重构与重新验证。当前用户未授权把原性能目标自动改为单路验收。

## 不使用 ARM 时的板级条件

- 标准相机接口连接 PL；I2C/SCCB 控制在 PL 中实现，不采用原资料里可能由 PS EMIO 驱动的相机控制流程。
- 使用 PL 侧 YT8531 千兆 PHY 和网口，MAC、MDIO 管理、以太网 FCS、IP/UDP 分包由 FPGA 实现。PS 侧网口不纳入此数据通路。
- 板载 512 MB DDR3 全部接在 PS 端，本版不将其当作 PL 可直接使用的帧存。FPGA 保留行缓存和短时 FIFO，边编码边发送；Ubuntu 保留完整帧及录像队列。
- PL 使用板载 50 MHz 晶振加 MMCM/PLL，不依赖 PS 提供 FCLK。先用 JTAG 下载调试；离线启动方式另行确认。
- 工具可能要求 PS7 的默认配置和必要启动设置，这与开发 ARM 图像应用是不同工作；板级封装时处理，不能将“只做 PL”理解为可忽略器件上电和配置要求。

本地总引脚表同时包含不同外设、重复端口和部分 7020 专用扩展信号，不能整份直接加入 7010 工程。正式约束仅选取实际顶层使用的时钟、复位、相机和 PL 网口信号，并按实物 PCB 版本复核。

## 带宽和展示

Ubuntu 可显示原始/处理后画面对照、编码画面、帧率、平均/峰值码率、每帧字节数、错误和缺片计数。第一阶段接收与解码即可形成完整展示，再加入录像或检测模型；无需在板上开发 Linux/NPU 应用。

接网口时先发计数数据，再发已知 JPEG，再接编码器输出。可用原始图像验证采集和传输：720p30 YUV422 有效负载约 55.30 MB/s、442.37 Mb/s，一条千兆链路在带宽上有验证空间；1080p30 则已约 995.33 Mb/s，尚未计入网络开销，不能持续完整传输。这是带宽计算，不是现有板上吞吐实测；最终 JPEG 演示仍由 FPGA 编码。

网传使用约 1400 字节 JPEG 数据一片，按通道、帧号和偏移重组，帧描述给出最终长度及状态。小 FIFO 无法吸收长时间的链路停顿：要核算最坏码量、输出突发和发送端服务间隔，溢出后废弃受损整帧并在 Ubuntu 显示错误。仅在符合运行条件的压力测试通过后，才能承诺无丢帧。

预处理先用流式灰度/亮度提取和 3×3 高斯滤波；直方图均衡、运动检测和更多 ILA 探针逐项加入，每次检查整机资源与时序。单路并非只有编码演示，仍可展示 FPGA 图像处理、压缩与网络传输的完整价值。

## 本次评估与复现

已完成 Vivado 2020.1 的 7010 OOC 综合：`CHANNELS=1`、`MAX_WIDTH=1280`、100 MHz，时钟约束在综合前加载。

| 资源 | 使用量 | 芯片容量 | 占用率 |
| --- | ---: | ---: | ---: |
| LUT | 10,160 | 17,600 | 57.73% |
| FF | 16,223 | 35,200 | 46.09% |
| BRAM Tile | 24.5 | 60 | 40.83% |
| DSP48E1 | 42 | 80 | 52.50% |

综合后内部 Setup WNS +2.083 ns、TNS 0，Hold WHS +0.208 ns、THS 0。只有模块内部估算时序，不包含物理布局布线、相机/RGMII 输入输出延迟或 CDC 验证；100 MHz 是候选工作频率。综合结果没有资源超限 DRC 错误、没有未解析黑盒，仍有 RAM 异步控制、DSP 流水级和 PS7 默认配置等 DRC 警告，以及本机 TclStore 写权限的启动警告。后续应处理整机复位与板级配置，未宣称零警告。

核心之外约剩余 7,440 LUT、18,977 FF、35.5 BRAM Tile 和 38 DSP。这个余量支持继续评估单路采集、精简 UDP/MAC 和简单流式预处理；每个新增模块仍需实际综合，不能提前认定完整系统放得下。优先避免全帧背景模型与大型 ILA。

原始证据：[资源统计](../reports/synth_xc7z010clg400-1_1ch_1280px_20260917_223219/utilization.rpt)、[综合后时序](../reports/synth_xc7z010clg400-1_1ch_1280px_20260917_223219/timing_synthesis.rpt)、[DRC](../reports/synth_xc7z010clg400-1_1ch_1280px_20260917_223219/drc_synthesis.rpt)。对应目录包含约束、综合脚本和 `build_manifest.json`，绑定参数及 RTL 哈希。本次只改了综合流程和文档，未更改 JPEG 算法 RTL、未生成可下载 bitstream。

```powershell
./scripts/run_synthesis.ps1 -Part xc7z010clg400-1 -Channels 1 -MaxWidth 1280 -PeriodNs 10
```

一般实施顺序为：单路核心资源确认 → 图样源编码 → PL 网口计数包 → Ubuntu 已知 JPEG 显示 → 相机接入 → 逐项预处理与压力测试。当前移植基线已完成的双路历史回归用于算法复用证据，不能自动替代 7010 单路参数和板级链路测试。
