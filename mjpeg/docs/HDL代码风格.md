# Verilog / SystemVerilog 代码风格

所有维护中的 RTL 和测试平台以 `rtl/core/` 的主体风格为准，参考
`rtl/core/dct/dct1d.v`、`rtl/core/quant/quantize.v` 和
`rtl/core/jpeg_encoder.v`。本规范只适用于 `.v`、`.sv` 和 `.vh`；Python、
Tcl、PowerShell 不在本次风格统一范围内。

- 每级缩进使用四个空格，不使用 Tab；去除行尾空白，文件末尾保留换行。
- 使用 `module name #(...) (...)` 布局。参数与端口分行列出；同方向、
  同类型且含义相关的短端口声明可以保留为一组，如 `input s_sof, s_eol, s_eof`。
- 实例采用命名参数和命名端口连接；多端口连接逐行展开，并在实例内对齐括号。
  保留现有测试平台中的 `.*` 连接，不为格式统一改动接口。
- `if (...) begin`、`end else begin` 与 `always @(...) begin` 的块首同行，
  块内逐条列出语句，不将多个赋值挤在一行。简单的单语句条件可以同行。
- 赋值和二元运算符两侧保留空格，逗号后保留一个空格；位宽、下标和切片
  沿用 core 的紧凑写法，例如 `[WIDTH-1:0]`、`data[i*16+:16]`。
- 长表达式按逻辑边界换行，续行缩进四个空格，目标行宽为 120 列。
  字符串、注释和不能合理拆分的内容允许超出。
- 保留现有的 `lower_snake_case` 模块／信号命名和大写参数／状态常量。
  不为排版重命名现有标识符，不改变层次路径或约束匹配关系。
- 沿用简短的英文 `//` 注释，解释接口、时序、握手和设计理由。
  格式整理保留原注释，不批量改写注释内容。
- 格式修改不得改变位宽、常量、运算顺序、阻塞／非阻塞赋值、复位方式、
  状态机、综合属性及预处理指令。应核对修改前后的 HDL 标记序列一致。

`rtl/core/` 保留为本次整理的基准；`rtl/generated/` 的查表头文件由生成器维护。
历史报告、构建副本和导出材料不作为源码批量改写。编辑器缩进设置见仓库根目录
`.editorconfig`。
