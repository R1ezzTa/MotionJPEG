# 同坐标块跳过：运行时可调死区

2026-09-27，按用户要求增加运行时阈值，目标仍为单路 1920×1080、30 fps。本模式是允许误差的实验，阈值为 0 时保留此前精确字节比较；非零时比较同坐标区域的反量化 DCT 系数。

## 调节方法

运行 PC 查看器，按板卡 KEY0 开启。在新增的“空间跳过系数阈值”输入框中填写 **0～255**，点击“应用”；“设为 0”恢复精确比较。运行时可以修改，不需要重新综合固件。查看器区分请求阈值、板卡读回设置和本帧实际使用的阈值。已有 KEY0/KEY1/KEY2/KEY3 与 LED 交互继续使用。

```powershell
& E:/anaconda/123/python.exe mjpeg/host/camera_viewer.py
# 指定初始阈值，仍等待 KEY0；附加 --auto-start 可由 PC 开始。
& E:/anaconda/123/python.exe mjpeg/host/camera_viewer.py --skip-threshold 32
```

输入框使用十进制。底层命令为 ASCII `T`、两位十六进制、LF，如 32 对应 `T20\n`。板卡仅在完整合法命令后更新设置；异常输入和不完整命令隔离，空闲约 100 ms 后复位解析器。PC 先核对固件能力再发送新命令；普通固件和抓包回放不能修改阈值。

阈值在一帧第一个像素握手时锁存，整帧保持一致。阈值改变后，下一帧完整刷新参考。复位默认值为 0；查看器省略命令行阈值时沿用板上现有设置，显式设置会在重新连接后再次应用。

## 比较含义与参考更新

每个区域仍为 64×8 像素、4 MCU。复用判断为该区域所有 Y/Cb/Cr 系数满足 `abs(current_quantized - reference_quantized) * Q <= threshold`。量化表项 Q 与 JPEG 实际编码一致；所有频率均检查，稀疏熵码中的隐含零系数也参加比较。阈值是**反量化 DCT 系数单位，不是亮度相差多少灰阶，也不是 JPEG 字节差值**；它不是单个像素误差的上限。

两个小型 Huffman 解码器从当前区域和缓存区域恢复稀疏系数，合并同一系数位置后比较。它们没有进行 IDCT、运动搜索或完整参考帧存储。解码异常时不允许 COPY，直接传输当前区域。阈值为 0 仍走旧字节相等路径，跳过选择与旧实验一致。

只有实际发送 DATA 后才替换缓存；COPY 时保留原缓存。因此始终与 PC 当前已重建的区域比较，缓慢累积的变化超过阈值后会更新。量化表改变、核心恢复、参考失步、阈值改变、每 30 帧周期刷新和新 START 会建立完整参考。周期刷新约每秒一次，并不保证消除全部噪声闪烁。

较高阈值会提高复用率，也会忽略真实细微变化。应同时检查噪声闪烁、细节停滞、缓慢运动和完整刷新时的画面变化。全局平均误差容易掩盖只有部分区域发生的较大误差，报告同时给出缓存覆盖区域的误差。

## 缓存范围和协议

板端仍缓存 192 个区域，每个最多 256 字节，间隔 21 个区域选取一个；1080p 总共 4050 个区域，坐标覆盖约 **4.74%**。超长区域和未缓存区域直接发送。此次修改没有扩展为整帧比较缓存，因而不能把局部稳定效果称为整张画面的降噪。

阈值实验负载为 **SPJ2**：在原 SPJ1 的帧前缀（magic、key u8、reference LE32）后增加 threshold u8，随后保持 HEADER、DATA、COPY 记录。PC 支持普通 JPEG、SPJ1 和 SPJ2；阈值改变而未完整刷新时拒绝提交参考。MBLK 帧描述符仍核对传输负载长度，PC 保存完整重建 JPEG。摄像头状态 flags bit31 表示支持阈值，bits23～30 为请求值；SPJ2 携带本帧实际值。

## 同输入离线证据

[历史实景连续 12 帧](../reports/ov5640/threshold_offline_20260927/summary.json)使用原抓包帧 100～111，保留原量化系数添加重启边界，再模拟当前板端缓存和阈值。原 MJPEG 共 6,510,795 字节，空间传输使用同一连续输入，不用不同时间拍摄的场景计算精确压缩率。

| 阈值 | 复用区域数 / 48,600 | 负载相对普通 JPEG | 缓存区域 RGB MAE | 缓存区域最大 RGB 差值 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | +6.9123% | 0 | 0 |
| 8 | 3 | +6.9106% | 0.0017 | 8 |
| 16 | 11 | +6.9064% | 0.0068 | 12 |
| 32 | 308 | +6.4288% | 0.6781 | 59 |
| 64 | 1,997 | +2.7140% | 7.2566 | 89 |
| 128 | 2,112 | +2.4398% | 7.7957 | 96 |
| 255 | 2,112 | +2.4398% | 7.7957 | 96 |

增大阈值确实提升了复用率。在此输入上，128 已达到所有 192 个缓存区域的复用上限，255 没有进一步收益；有限覆盖率仍无法抵消重启和记录开销。MAE/最大差值是相对原 JPEG 的 RGB 数值变化，不能直接判断主观画质更好。当前实景噪声和局部误差的结果不代表所有场景。

额外的[完整 PC 缓存参考模型](../reports/ov5640/threshold_offline_fullcache_20260927/summary.json)覆盖全部区域，阈值 32 在同输入上减少负载 3.45%，全画面 RGB MAE 0.696、PSNR 39.90 dB。这是 PC 离线模型，不是本板实现。阈值 128 虽大幅减少负载，但连续 11 帧完全冻结，不能将时间变化为零直接称作画质改善。
