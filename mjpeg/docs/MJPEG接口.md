# 连续 MJPEG 接口

## 本版接线

`mjpeg_encoder` 是给 A、B、C 合并时使用的内部顶层。默认双路，每路有独立 JPEG 核心；`CHANNELS` 支持 1～4。`mjpeg_synth_top` 为独立综合顶层，将配置和输出改为两条 32 位总线。原来的 `jpeg_encoder`、`jpeg_synth_top` 保留。

一帧仍编码成一个完整 Baseline JPEG，无帧间预测。压缩质量沿用原量化表接口，每路可在帧间更新。这里的“视频”由连续帧、帧号和时间信息表达；AVI、网络协议、DDR、摄像头驱动不在本模块中。

## A → B

所有信号须在 `clk` 域。第 c 路像素为 `s_data[c*16+:16]`，一次握手接收一个像素。彩色模式：低 8 位为 Y，高 8 位按 Cb、Cr 交替，偶数列 Cb，奇数列 Cr；采用全范围 YCbCr 4:2:2。灰度模式只读低 8 位。

像素与 `s_sof/s_eol/s_eof` 必须一起保持，直到该路 `s_valid && s_ready`。SOF 只在第一个像素，EOL 在每行最后一个像素，EOF 在整帧最后一个像素。禁止用 ready 直接停摄像头：A 需要缓冲采集数据。实际缓冲容量要按采集时钟、突发速度与编码停顿另行计算。

每路独立配置宽、高、灰度模式和 128 项量化表。灰度宽为 8 的倍数，彩色宽为 16 的倍数，高为 8 的倍数，最大宽默认 1920；尚无边缘补齐。参数应在 SOF 前完成，量化表修改须握手。帧中修改尺寸、模式不改变已开始的帧；量化表写入会被拒绝。`enable` 应保持到该帧结束，关闭它会暂停接收。

首次加载或核心复位后重载量化表，`tables_ready` 在最后一个有效表项握手后再等待两个上升沿才置位。A 应遵守 `s_ready`，配置方可等待 `tables_ready`；不能按写入次数推断就绪。已经完整加载的量化表在帧间更新时，就绪保持有效。

`s_timestamp[c*64+:64]` 在第一个像素握手时锁存，推荐由 A 提供采集时间戳。每路帧号从 0 递增。全局复位后帧号归零，量化表需要重载；C 应同时清空旧帧重组状态。

采集丢数据或需要取消未完成帧时，该路拉高 `s_abort` 一拍。B 终止该帧，输出零字节结束标记和错误描述，并自动恢复缓存的量化表。恢复约 260 拍，此期间该路不收像素；以 `tables_ready` 和像素握手为准。帧已输出结束标记后再 abort 不生效。没有自动超时计时器，A 须负责识别采集异常。

## B → C（内部 128 位接口）

输出按数据块轮询，各路 JPEG 可以交错。C 必须按 `m_channel + m_frame_id` 分别重组，不能把整条总线直接存成一张 JPEG。

`m_data` 低字节先发送，`m_bytes` 为 1～16。`m_first` 标识该路这一帧的首块；`m_last` 标识末块。中断标记为 `m_bytes=0 && m_last=1`，C 应丢弃该帧全部已收字节。背压时，数据与全部标签保持不变。

正常末块包含 JPEG 的 EOI。末块被下游接收后，B 才发送该帧描述。描述与像素流使用独立握手，记录通道、帧号、时间戳、实际 JPEG 字节数、宽高、灰度模式和错误状态。

|状态位|含义|
|---|---|
|0|主动中断|
|1|SOF/EOL/EOF 标记与尺寸不符|
|2|编码系数超范围|
|3|配置错误|
|7:4|保留，零|

非零状态帧建议丢弃。单路至少允许一个描述寄存器，加上共享两项描述 FIFO；描述持续不被读取最终会使相应通道暂停开始新帧。下一帧可以在上一个描述进入共享 FIFO 后开始，描述 FIFO 中的标签不会随之改变。

## 独立顶层的配置总线

`cfg_channel` 选路。命令在 `cfg_valid && cfg_ready` 时生效；同一时钟仍保持上一条命令的数据，直到握手。实际握手的配置命令会暂停该路像素握手，防止同拍修改配置与 SOF 的歧义。忙碌通道拒绝配置，等待中的命令不会暂停当前帧，可以保持 valid 等待帧结束。无效命令也不影响像素接收。

|cfg_cmd|cfg_data|
|---|---|
|0|[15:0] 宽，[31:16] 高|
|1|bit0 使能，bit1 灰度|
|2|[6:0] 量化地址，[14:7] 量化值，暂存一项|
|3|[20:0] 倒数，提交此前暂存项|

量化值 q 为 1～255，倒数为 `ceil(2^20/q)`。地址 0～63 为 Y 表，64～127 为色度表，均按自然顺序。无效通道、命令 4～7不握手。默认顶层的时间戳为 B 时钟计数，表示首像素被接收的时间；系统集成时可改用内部顶层的 A 时间戳。

## 32 位传输封装

这是板内传输格式，C 解包后得到标准 JPEG。`m_packet_last` 是传输包结束，不是 JPEG 帧结束；`m_bytes` 是该 32 位字的有效低位字节数。包内字按下表顺序，字内低字节先发送。长度和标志可跨包重组一帧。接口背压需一直保留完整包。

包头 word0：

|位|内容|
|---|---|
|31:16|0x4D4A|
|15:12|版本 1|
|11:10|类型：0 JPEG 数据，1 帧描述|
|9:8|通道号|
|7|本帧首块|
|6|本帧末块|
|5|中断标记|
|4:0|本数据块字节数 0～16，描述包为 0|

数据包：word0 包头，word1 帧号，随后 `ceil(字节数/4)` 个数据字。零字节中断包只有两字，末块、中断位均为 1。正常数据包的最后一个字可能仅有 1～3 字节。

描述包固定 7 字：word0 包头；word1 帧号；word2 时间戳低 32 位；word3 高 32 位；word4 JPEG 字节数；word5 高 16 位为高度、低 16 位为宽度；word6 bit8 灰度，bit7:0 状态，其余零。

每 16 字节 JPEG 增加 8 字节包头，满包封装开销约 50%。这是一种简单可验证的合并接口；后续传输可以在 C 侧聚合成更大包，或用内部 128 位接口携带侧带标签，避免把这份开销带上网络。网络带宽应按实际图像、量化质量和传输格式另行预算。

## 验证与接板范围

验证报告见 `reports/MJPEG验证结果.md`。200 MHz 的布局布线只使用时钟约束，独立顶层引脚为工具自动分配。接入实际板卡前仍需替换引脚、补齐输入/输出延迟和复位释放约束，验证 A 缓冲、CDC 与传输链路。当前测试衡量遵守 ready 的输入流，不代表摄像头已经上板通过。

C 的参考解包代码为 scripts/mjpeg_receiver.py，接收已握手的 32 位字、有效字节数和包结束信号。它按通道与帧号保存数据，等帧描述到达后返回完整 JPEG；非零状态帧返回 jpeg=None。总线采样 CSV 的命令行为 `python scripts/mjpeg_receiver.py transport_words.csv output_folder`。
