# OV5640 补光灯上板测试

2026-09-26 已在实际达芬奇 A35T 和 ATK-OV5640 上验证补光灯开关。用户现场确认：**两颗补光灯都亮起约 2 秒，随后自动熄灭**。摄像头保持 VGA 640×480 YUYV、100 MHz FPGA 编码、60 MHz USB FIFO；测试结束后灯灭、编码停止。

## 控制实现

本地官方《达芬奇之 FPGA 开发指南 V2.3》第 1254–1255 页说明，模块 LED1/LED2 由摄像头 STROBE 引脚控制：`3016=02`、`301c=02` 选择 GPIO 输出，`3019=02` 开灯、`3019=00` 关灯。

初始化保持灯灭，去掉原例程中开灯后立即关灯的启动闪光。新增 USB 单字节命令 `L` 请求补光，`l` 关闭，`S` 停止编码时也取消补光。FPGA 独立计时，每次 `L` 请求约 2 秒后关闭；重复 `L` 会重新计时。这个上限采用官方“不建议一直点亮或者点亮时间太长”的使用建议。

开关使用现有 SCCB master 写 `3019` 并读回确认。每步最多重试 2 次；持续 NACK 或读回不符则拉低摄像头 RESET，报告 `light_error`，重新打开 USB 设备会重新初始化。状态 flags bit8/9/10/11 分别为请求、读回确认、控制错误、事务忙。`light_on` 是寄存器状态；物理发光另由用户现场确认和实际图像验证。

## 实测结果

固件：[build_20260926_164734](../reports/mjpeg_board_test/build_20260926_164734/build.log)。建立/保持裕量为 +0.064/+0.040 ns，CDC 无 Critical，DRC 0 错误、保留原有 69 个警告；JTAG 下载后 DONE/EOS=1、CRC ERROR=0。

接收目录：`reports/ov5640/light_20260926_165421/`。主机在约 2.001 秒仅发送一次 `L`，直到约 8.003 秒停止时才发送 `l`。板端第 3、4 秒状态为开灯，第 5 秒起为关灯，因此关灯发生在主机关灯命令之前，验证了 FPGA 自动关闭。

|---|---|
| JPEG 接收、独立完整解码 | 117 帧全部通过，失败 0 |
| 时间戳帧率 | 15.00001 fps；稳定一秒窗口输入/成功压缩均为 15 |
| 稳定窗口丢帧、FIFO 溢出 | 丢帧增量 0，溢出累计 0；启动阶段 1 帧未准入跳过 |
| 补光控制 | 开灯读回确认、自动关灯读回确认，控制错误 0；用户现场确认两颗灯正常亮灭 |

## 重跑

```powershell
python mjpeg/host/camera_receiver.py --ftdi --duration 8 --light-pulse --light-after 2 --save-count 120 --output mjpeg/reports/ov5640/light_test
```

脚本先接收正常图像，再请求一次点亮。2 秒到时不发送 `l`，用状态检查 FPGA 自动关灯；停止和异常清理时另发 `l`。同一时刻只能运行一个接收程序。数码管显示成功压缩帧率，停止编码后归零。

初始化仿真覆盖开关及读回、无主机取消时的自动关闭、SCCB 写入过程中取消、关灯 NACK 到重试上限后复位、读回错误复位，以及原有芯片识别和初始化故障。主机协议和计时测试共 20 个通过。
