# RESET 后数据流恢复（2026-09-26）

用户报告按 RESET 后数据失效。旧 PC 预览日志确认 `ValueError: Invalid block header`，此前已连续接收 44,152 帧、编码失败为 0。

RESET 复位 FPGA 时钟、采集、编码、FIFO 和封包状态，立即中止当前帧；外部 FT232H 芯片和 PC 缓冲区没有跟随 FPGA RESET 一起清空。旧半包与复位后的新数据拼接会破坏 MBLK 边界；即使正好在包边界复位，帧号、时间戳、FPS 和 USB 统计窗口归零也会使旧会话的连续性校验失败。旧查看器对此直接终止接收，所以窗口不能恢复。该故障属于复位后的通信会话恢复问题。

修改 `camera_viewer.py`：实时解析或 USB 异常时重开设备，清理解析器及未完成帧，重置帧号、时间戳和状态窗口校验，清除旧预览及遥测，记录恢复次数和原因。默认不发送自动启动命令，等待 KEY0；显式 `--auto-start` 保留重新启动行为。连续恢复失败最多重连 3 次，此后报告错误；关闭程序时不继续重连。总运行时限不会因恢复重新计时。离线抓包和独立严格接收器继续拒绝异常数据。

修改 `ftdi_fifo.py`：USB 参数配置及 FT_Purge 在开启同步 60 MHz CLKOUT 之前完成。板载运行选择可以跨 USB 链路复位保留，若先开启时钟再清缓冲，可能删掉 FPGA 自动发送的新 START 包，只剩 JPEG 中段，造成 `JPEG outside stream`。新顺序保留完整起始数据。本次没有修改 RTL 或已验收的板载按键功能。

验证覆盖：运行中半帧/半包截断恢复并接受新帧号 0、待机状态 FPS 窗口归零恢复、持续坏数据的有限重试、普通启停、离线损坏仍报错，以及 FTDI 初始化次序。

实板验证使用当前已验收 `build_20260926_204044` 位流，在主机接收运行中通过 JTAG 重新配置模拟硬复位；这不是声称已经自动按下物理 RESET 键。复位触发一次 `FPS sequence` 恢复，丢弃 1 个未完成帧。查看器恢复被动等待，随后经兼容 C 命令启动第二次接收，共 593 帧全部独立解码，最终正常 STOP/END，没有致命错误，FIFO 溢出 0。证据在 `reports/ov5640/reset_recovery_20260926/summary.json`。第二会话重新从零计数通过协议校验；状态定时采样未恰好记录帧号 0，不以采样记录声称目视捕获了该帧。

用户可在新版窗口中按 KEY0 启动、按 RESET 后释放、等待重新初始化，再按 KEY0；窗口应自动恢复，无需退出重开。物理 RESET 键的本次复测仍待现场确认。
