# 偏色定位记录（2026-09-26）

2026-09-28 更新：实板 RAW、通道增益、内部色条及实景反证进一步确认当前 ISP 翻转配置与光学 RAW 相位不匹配。仅改 FPGA 为 GRBG 会使实景偏紫；采用 profile 5 `3820=42` 配合 BGGR 后，明显绿调大幅减弱。完整证据及尚未完成的色彩校准见[RAW 偏色定位与修正](RAW偏色定位与修正.md)。下文保留 2026-09-26 时的检查结果与当时尚未确认的疑点。

当前优先检查摄像头 RAW 配置与 FPGA 颜色重建的匹配，包括 Bayer 相位和白平衡增益。现有证据可以基本排除 PC JPEG 解码器造成全局绿色偏色，尚不足以唯一确定摄像头寄存器、FPGA 前处理或物理采集的根因，不能宣称已排除模块损坏。

使用同一个实板 JPEG `reports/ov5640/board_controls_20260926_204800/sample_q85.jpg`，1920×1080、545,495 字节。先读取文件元数据，随后只计算既有墙面区域 `(1200,250)-(1350,600)` 的像素统计，没有查看或嵌入图像。

| 解码器 | 平均 R | 平均 G | 平均 B | G / ((R+B)/2) |

| Pillow | 123.8340 | 192.5440 | 135.7035 | 1.483747 |
| Windows GDI+ | 123.8349 | 192.5445 | 135.6979 | 1.483778 |

两套解码器各通道均值的最大差异小于 0.006（0–255 范围），全局偏绿表现一致。由此判断偏色已存在于 JPEG 表达的像素中，优先检查编码之前的颜色链路。该区域的墙面真实颜色、照明和曝光未标定，上述比值不能当作标准白平衡校准结果。机器可读证据见 `reports/ov5640/cross_decoder_color_20260926.json`。

## 当前颜色链路与未排除项

当前 profile 5 设置 `4300=00`、`501F=03`，FPGA 将输入按 BGGR Bayer 数据插值为 RGB，再转换为全范围 JPEG YCbCr422。`bayer_bggr_to_yuv422.v` 没有额外白平衡增益和颜色校正矩阵；固定 BGGR 与实际裁剪、翻转和首行首列是否严格匹配，还需要真实 RAW／已知颜色目标核对。算法对假定 BGGR 输入的仿真通过，不等于已验证传感器实际 Bayer 相位。

OV5640 数据手册将 `501F=03` 定义为 DPC RAW，`4300=00` 定义为 BGBG/GRGR 输出；白平衡是独立控制功能。初始化设置 `5001=83`，AWB 使能位为 1，因此不能简单宣称“没有打开传感器 AWB”；也不能仅凭该位就认为 RAW 输出已经完成正确色彩校准。资料：[OmniVision OV5640 数据手册，Waveshare 镜像](https://files.waveshare.com/upload/d/da/OV5640_DataSheet.pdf)，5.3、5.12、6.5 和 7.4 节。

此前将 `501F=03` 改为 `05` 的实拍对照没有修复偏绿，已恢复原配置，不能把单个格式选择寄存器当作已确认根因。

三档画质的 690 帧及此前 60 秒的 1796 帧均可独立解码，稳定传输和 FIFO 检查通过；这支持 JPEG/USB 链路稳定，但不能证明传感器像素、DVP 数据位、排线或高频采样完全正确。若完成颜色相位和白平衡核对后仍异常，应以已知正常配置和替换模块对照定位物理问题。

后续定位应使用已知中性目标及红蓝目标，先确认 Bayer 相位，再检查 RAW 白平衡是否生效，并对比已知配置的低速 YUV 输出。尚未进行这些新实拍或模块替换试验。本轮没有修改 RTL、摄像头配置或已验收按键固件。
