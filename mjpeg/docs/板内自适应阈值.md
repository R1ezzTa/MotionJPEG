# 板内分区域自适应阈值实验（2026-09-28）

第一版在 FPGA 内结合 DDR3 区域参考缓存完成自适应判断，PC 只设置模式、上限并显示结果。不做运动搜索或补偿，不依赖 PC 每帧反馈。

## 当前策略

区域仍为 64×8，彩色 1080p 共 4050 个。每区域使用 4 bit 状态：2 bit 容差等级、2 bit 连续 COPY 次数，总计 2025 字节逻辑容量。DDR3 保存上次实际发送的熵码；COPY 不改参考，DATA 在传输和内存写提交后更新参考及状态。

用户设置的 T 在手动模式下仍是固定系数阈值，在自动模式下成为上限。局部四档为 `T>>2`、`T>>1`、`T-(T>>2)`、`T`；例如上限 60 对应 15、30、45、60。首次完整刷新后从最低档开始。

对当前和已发送参考的反量化 DCT 系数差，自动模式要求：

- 每个差值绝对值不超过上限 T。
- 每个 8×8 块的 DC、前五个 AC，以及所有 Cb/Cr 系数，差值不超过 `T>>1`。
- 整个区域全部系数差的绝对值之和不超过 `64*T`。
- 所有差值还需不超过当前区域档位，才允许 COPY。

前三项全部通过，则该区域下次升一档，最高保持第四档；即使因当前局部档位较低而发送 DATA，仍可学习升档。前三项失败或熵码异常，发送 DATA 并回到最低档。这个“稳定”判据是受限系数变化的启发式判断，**不是已证明能区分所有运动与噪声，也没有估计真实噪声方差**。缓慢运动、细纹理或噪声较强时，仍可能误判或没有复用收益。

非零上限下，最多连续 COPY 2 次，下一次强制发送当前区域；强制更新保留已学到的档位。T0 使用原来的精确字节比较，不允许新增损失，因此不受此两次限制。周期完整刷新仍每 30 帧一次；模式、上限、画质或尺寸变化、新 START 和参考失步仍完整刷新。局部自动升档不会触发整帧刷新。

自动模式每区域的双熵码比较另有 384 个核心时钟周期的预算，100 MHz 下为 3.84 μs。超时立即停止比较，发送当前 DATA，并把该区域档位降回最低档；不把尚未比较的系数视为相同，也不直接中止整帧。该预算只约束系数比较阶段，不包含 DDR 取数和 DATA 发送时间，不构成所有图像内容都能达到 30 fps 的保证。手动模式和 T0 精确比较保持原有路径。

非零上限的自动模式还优先处理输入队列：如果另一块熵码缓冲已存满后续区域，当前区域直接 DATA；若还没提交 DDR 参考读命令则不再读取，若比较已经开始则结束比较并清空两路局部解码流水线。只在输入队列有空余时继续尝试复用。此时区域档位同样回到最低档。这项取舍把持续采集放在复用收益之前，队列繁忙时带宽可能接近 T0；不是用丢帧来节约传输。

更直接的触发源是采集像素 FIFO 的读时钟域水位。利用已有两级 Gray 写指针同步后计算占用，并注册输出；达到 FIFO 四分之一容量即触发上述 DATA 优先规则。当前 4096 像素 FIFO 在约 1024 像素时触发，留出剩余容量吸收在途像素和 DATA 发送延迟，不增加未同步二进制跨时钟总线。复位和 flush 清零水位标志。模式为手动或上限为 0 时，此新增保护不改变原来的比较规则。精确比较还必须确认 DDR 参考已经加载，避免积压分支跳过参考读取后误用旧局部缓存。

这限制的是区域旧参考年龄，并不能保证 2 帧内快速运动看起来没有拖影。安全边界是判断不确定时更多地发送 DATA，收益需要与手动 T60 和 T0 实拍对照。

## 模式与操作

新固件复位默认仍为手动、T0、Q85、停止、关灯。KEY0/1/2/3 和 LED 映射保持原有行为。USB `A1\n` 开启自动，`A0\n` 关闭；`Txx\n` 设置手动阈值或自动上限。两个命令都原子提交，畸形字节不会被当成启停/补光命令。

查看器增加“板内自适应”复选框，并根据板卡能力开放。也可直接运行：

```powershell
& E:/anaconda/123/python.exe mjpeg/host/camera_viewer.py --adaptive --skip-threshold 60
```

默认仍等待 PC“开启传输”或 KEY0。关闭自适应后以同一数值比较手动 T60；设为 0 可建立无额外损失基线。每帧统计显示实际模式及上限，不把局部四档误写成一个全画面实际阈值。

SPJ2 的 flags bit 1 表示自动模式，bit 0 继续表示完整刷新；DATA/COPY 字节记录不变。PC 校验模式变化必须伴随完整刷新。相机状态 flags bit 7 表示请求自动模式，配置索引字段 bit 9 标记支持能力，低 9 bit 仍是初始化索引。

## 验证

独立 Python 系数参考与 RTL 的 88 帧逐字节一致，覆盖低档学习、连续两次复用后强制更新、DC/色度变化、多个小 AC 差值的累计保护、手动/自动切换、T0、上限变化以及全部 4050 个位置和末区 4049。其中 20 帧使用缩短至 8 周期的预算，验证未完成比较只能发送当前 DATA、两路解码器清空、后续精确/手动模式不受影响；20 帧以快速输入验证队列积压时 DATA、密集后续区域尚未填满队列时仍可正常 COPY；另 20 帧验证像素输入积压时非零自动模式全部 DATA，而 T0 精确/手动模式不受影响。基础复用向量使用有间隔的输入提供比较空余时间。测试使用随机输出反压和内存事务模型。

原手动模式 12 个阈值样例、密集系数、末区累计漂移、提前 DATA、畸形熵码及 DDR 恢复回归通过。自动模式另验证八次完整参考恢复：读/写/未接受命令中断、DDR 写反压、全局复位、较晚的量化失效，以及双系数解码器同时活动时中断。86 项主机回归通过。

纯时间预算版本另从实拍 T0 抓包取出两帧 1920×1080 JPEG，以自动上限 96 在 RTL 中重放，检查两帧共 8100 个位置。首帧完整输出与源 JPEG 一致；第二帧的 DATA 与当前源区域逐字节一致，502 个 COPY 与参考区域一致，并逐个独立检查系数峰值、DC/色度和累计保护。该帧跳过模块消耗 1,928,989 核心周期，但使用理想内存模型，不能用这项结果代替摄像头实测帧率。历史记录保存在 `work/adaptive_20260928/first_captured_budget_summary.json`；加入输入队列优先规则后重新验证。

## 首版实板问题与修正

首版 `full_20260928_115000` 已完成上板对照：T0 约 15.23～15.33 MB/s，手动 T60 约 2.17 MB/s，自动上限 60 约 13.76 MB/s，均约 30.002 fps。自动上限 60 的 60 秒测试通过 1800 帧、零 FIFO 溢出。抓包验证自动非零最多连续 COPY 2 次，手动 T60 同一位置则曾连续复用 29 帧。三档画质、补光读回、两次启停通过 690 帧；实际 Tk 窗口内切换模式、设 0、暂停显示和再次启停通过 280 帧。

但上限 96 的首轮扫描在第二帧比较时中止。独立 5 秒诊断复现：117 个帧描述符中 58 帧失败、59 帧完整解码，板内状态为输入 30 fps、完成 15 fps、失败 15 fps，并读到 FIFO 溢出。大上限使比较较难提前结束，首轮区域仍处于低档而多数区域又需要 DATA，长比较阻塞当前像素输入。因此增加上述比较预算后重新构建；原失败记录保留在 `mjpeg/reports/ov5640/adaptive_ceiling_20260928/` 和 `work/adaptive_20260928/auto96_diagnostic.json`。不能用 T60 的通过结果把这次失败略去，也不能把帧中止后的低带宽当成压缩收益。

纯时间预算版本 `full_20260928_121003` 在上限 0、32、60、96 各通过 120 帧，约 30.002 fps；但上限 128 的第二帧仍中止，保留失败扫描在 `mjpeg/reports/ov5640/adaptive_budget_auto_20260928/`。固定比较时长没有跟踪瞬时输入队列压力，因此再加入上述队列优先规则并重新构建。

仅观察编码后双缓冲的 `full_20260928_122633` 仍在上限 128 中止，失败扫描保留在 `mjpeg/reports/ov5640/adaptive_queue_auto_20260928/`。编码块队列不能及时代表上游像素 FIFO 的积压，因此继续加入直接水位反馈。新的强制积压仿真同时发现“跳过参考读取后仍可能落入精确比较”的分支漏洞，已经堵住；其未通过输出和日志保留在 `work/adaptive_20260928/adaptive_pressure_sim.log`，修正后的 88 帧完整输出校验通过。像素 FIFO 四分之一水位的升降、指针回绕、停钟复位/flush 和六种采集格式、采样边沿组合均回归通过。

## 最终上板结果

最终固件为 [full_20260928_124800](../reports/ddr3/full_20260928_124800/davinci_mjpeg_board_test.bit)，已经通过 JTAG 下载到 FPGA SRAM，DONE/EOS 为 1，CRC 错误为 0；没有写 SPI Flash。bitstream SHA256 为 `f2ca180f5410d7de5975eb30419e9a7957743c9e7d3c4d698df1eacfe79fc8fc`。下载及验收核对了 166 项源文件/构建产物散列。源快照保存在 `work/adaptive_20260928/source_snapshot/`。

布局布线后 WNS 为 +0.064 ns、WHS 为 +0.040 ns，TNS/THS 均为 0；LUT 18496/20800（88.92%），FF 20881，BRAM36 等效 32.5，DSP 46。原相机配置 profile 5 和偏色修正保持不变。

实板严格解包并用独立 JPEG 解码器验证了 **3570 帧 1920×1080**，全部通过，平均约 **30.002 fps**，相邻帧时间戳最大间隔 **33.33117 ms**，各项测试均无相机 FIFO 溢出。其中：

- 自动上限 0、32、60、96、128、255，各 120 帧，共 720 帧。
- 手动 0、60、0，各 120 帧，共 360 帧。
- 自动上限 60 连续 60 秒，共 1800 帧。
- 三档画质、补光约 2 秒自动关闭读回、两次启停，共 690 帧。

实际 Tk 窗口另收到 281 帧、显示 166 帧，解码失败、参考恢复和 FIFO 溢出均为 0；两次切换手动/自动、自动设 0、暂停显示时继续接收、两次 PC 启停和线程正常退出均通过。显示帧数少于接收帧数是预览更新采样，不代表板卡传输失败。此次没有重新实测物理按键、LED 和灯的现场表现，保留此前用户确认；快速运动色块/拖影的主观改善仍待现场对照。

在全部 4050 个位置逐帧统计连续 COPY 年龄，手动 T60 实测最大 29 帧；所有测试过的非零自动上限均最多 **2 帧**。T0 抓包没有 COPY。年龄限制验证通过，不能据此声称运动画质已经合格。

此版本为限制旧参考滞留和保持采集吞吐，会频繁发送当前 DATA；实际噪声、严格系数保护以及比较阶段的处理压力共同限制了 COPY 比例。自动上限 60 短测仅复用 9528/486000 个区域（1.96%）。各档自动模式的图像载荷还大于其重建 JPEG 大小，说明当前复用不足以抵消区域记录开销；重建 JPEG 已包含复用历史，这个比值也不能当作相同输入下与普通 MJPEG 的比较。自适应功能及稳定性验证完成，但不能把这一版描述为已经解决带宽与画质的折中。
