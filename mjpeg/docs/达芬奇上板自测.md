## 板上预期现象

| 操作 | 预期现象 |
| --- | --- |
| 正常运行 | LED0、LED1 每 0.5 秒交替亮；LED3 常亮；LED2 默认灭 |
| 按住 KEY0 | LED2 亮，松开后灭 |
| 按住 RESET | 四盏用户 LED 全部熄灭 |
| 松开 RESET | LED0、LED1 重新交替，LED3 恢复常亮 |

这里的 LED0～LED3 是四盏红色用户灯，不包括电源灯和配置 DONE 指示灯。用户对上述现象回复“全部符合”，因此 LED 闪烁、KEY0 响应和 RESET 熄灯行为已获得现场确认。该观察验证了时钟驱动逻辑工作，不是对晶振频率的精密测量。

## 复现

在工程目录的 PowerShell 中执行：

```powershell
./scripts/run_board_selftest.ps1 -Action Build
./scripts/run_board_selftest.ps1 -Action Program
```

仅查询配置状态：

```powershell
./scripts/run_board_selftest.ps1 -Action State
```

脚本默认使用 `F:/Xilinx/Vivado/2020.1`。下载前核对 JTAG 下载器序列号、芯片 IDCODE 和构建文件校验值；下载后检查配置完成状态及 CRC / DONE / EOS。

自测采用独立的 Vivado 非工程构建流程；`mjpeg.xpr` 当前仍是 `mjpeg_synth_top` 编码器模块配置。LED 自测的约束仅用于这个自测设计，没有作为编码器内部总线的板级约束加入主工程。

## 结果边界

当前证明了自测设计可以完成物理实现、生成 bitstream 并经 JTAG 配置到实际 A35T。该设计不包含 JPEG 编码器、摄像头采集、FT232HL 数据读写或 DDR 控制，不能作为完整图像链路通过的证据。

结果分层：构建及下载检查由工具完成，LED / 按键现象由用户现场确认，基础板卡自测通过；完整图像系统验证仍待接入对应模块后进行。
