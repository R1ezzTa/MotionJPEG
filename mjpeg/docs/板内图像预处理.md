# 板内灰度、二值化和 Sobel

当前主工程已移除 DDR3，历史构建和资源数字保留原记录。当前实现及验证入口见 [无 DDR3 图像链路](无DDR3图像链路.md)。

在已有彩色模式上新增三种可切换模式，全部在 FPGA 的 JPEG 编码前处理。PC 只发送控制命令并解码收到的 JPEG，保存按钮保存板卡实际编码结果。

| 模式 | 编码前亮度 Y | 编码前 Cb/Cr | 参数 |
|---|---|---|---|
| 彩色 | 原亮度 | 原色度 | 无 |
| 灰度 | 原亮度 | 128 | 无 |
| 二值化 | Y≥亮度阈值为 255，否则 0 | 128 | 亮度阈值 0～255，复位 128 |
| Sobel 边缘 | 保留达到阈值的边缘强度，其余为 0 | 128 | 边缘阈值 0～255，复位 32 |

Sobel 使用当前帧 3×3 亮度邻域、标准横纵 Sobel 核与反射边界。强度为 `min(255, (abs(Gx)+abs(Gy)+2)>>2)`，保留灰阶强度，阈值用于去除弱边缘。边缘阈值越小，保留的弱边缘和噪声越多；越大，边缘越少。阈值 0 输出完整梯度，恒定亮度仍为黑色。它与二值化的亮度阈值含义不同。

保留已有稳健降噪 v2 的独立开关和强度控制。完整链路为 RAW BGGR 重建 → 当前帧降噪（可关）→ YUV422 预处理 → 独立 JPEG → USB。没有历史帧、帧间预测、运动补偿或 DDR 参考复用。预处理共用两个 1920×16 位行缓存，不保存整帧；彩色模式经同样窗口延迟后逐像素原样输出。JPEG 继续使用既有彩色 4:2:2 格式；三种灰度模式的色度恒为中性，解码后为灰度图。二值化在编码前只有黑白，JPEG 的有损量化可在边界产生灰阶及振铃。

模式、亮度阈值和边缘阈值在预处理入口接受 SOF 时一起锁定，本帧中途修改会在后续帧生效。状态中的“实际模式”是预处理输出 SOF 被编码器接受时的设置；约每秒回报一次。停止时只更新请求，启动新帧后才更新实际设置。USB 命令各自原子提交；PC 一次应用按 B、E、M 顺序发送，运行中可能相隔一个帧边界，但单帧内不会混用设置。

## 使用

运行 `python mjpeg/host/camera_viewer.py`。窗口新增“彩色／灰度／二值化／Sobel 边缘”四个按钮、亮度阈值、边缘阈值和“应用阈值”。先按“开启传输”或 KEY0，再选模式。修改参数后点“应用阈值”或回车。状态栏显示板卡实际模式、两个实际阈值及等待生效的请求；没有回报、旧固件及抓包回放时禁用修改。

```powershell
& E:/anaconda/123/python.exe mjpeg/host/camera_viewer.py --preprocess-mode gray
& E:/anaconda/123/python.exe mjpeg/host/camera_viewer.py --preprocess-mode binary --binary-threshold 128
& E:/anaconda/123/python.exe mjpeg/host/camera_viewer.py --preprocess-mode sobel --edge-threshold 32
```

CLI 省略参数时保留板卡设置，默认不自动开启传输；可加 `--auto-start`。复位默认彩色、亮度阈值 128、边缘阈值 32、降噪 0、Q85、停止、关灯。KEY0 启停、KEY1 切画质、KEY2 限时补光、KEY3 停止并关灯及原 LED 映射继续使用。

## 控制与状态协议

USB ASCII 命令使用两位十六进制值和 LF：`M00\n` 彩色、`M01\n` 灰度、`M02\n` 二值化、`M03\n` Sobel；`Bxx\n` 设置亮度阈值，`Exx\n` 设置边缘阈值。非法模式、非法十六进制、缺少 LF、超长消息均不提交；错误消息排空至 LF 或 100 ms 超时。载荷里的 C/S/L 不会触发启停或补光，物理按键仍能操作。既有 N/T/A 命令按各自固件能力门控。

CAM1 仍为 MBLK kind 7、32 字节，配置字 bit 12 表示预处理能力，不占用 SCCB 索引 bits 8:0 或 VSYNC 高位。新增独立状态 MBLK kind 8、12 字节，三个 LE32 字：

| 字 | 内容 |
|---|---|
| 0 请求 | bits 31:24 为版本 1；23:18 保留 0；17:16 模式；15:8 边缘阈值；7:0 亮度阈值 |
| 1 实际 | bits 31:18 保留 0；17:16 模式；15:8 边缘阈值；7:0 亮度阈值 |
| 2 帧数 | 自复位以来接受的预处理输出 SOF 数，包括后续可能中止的帧 |

状态和 CAM1 来自同一个 FPS 采样的快照，发送过程中不修改。新主机可回放旧 kind 0～7 抓包；新固件新增 kind 8，必须使用已更新的 `block_records.py`。

### 首轮问题记录

第一轮彩色测试将全分辨率 NumPy 统计放在 USB 读取线程，第三个正常帧后出现中止；改为后台统计后同一固件通过前五档共 450 帧。首轮 Sobel 使用 `强度≥阈值→255` 的纯黑白输出，阈值 8、降噪关闭时把弱边缘和噪声全部放大，实测连续采集溢出，无法编码完整帧。该实现未接受，最终改为保留边缘强度、只抑制低于阈值的部分，二值化仍提供纯黑白模式。首轮 bit `full_20260928_210508`、失败抓包与日志保留在 `reports/ddr3/preprocess_acceptance_20260928/sweep*` 和 `work/preprocess_20260928/`，不能作为最终通过记录。

## 最终实板验收

最终安装 `full_20260929_153849/davinci_mjpeg_board_test.bit`，SHA256 `39e7fd4ead0514ea3c433edd8314a978f3f1b91bf83041a2e1dea353e802201a`。JTAG CRC ERROR=0、DONE=1、EOS=1；安装至 FPGA SRAM，没有写 Flash。验证 172 个构建及安装哈希，源快照在 `work/preprocess_20260928/final_source_snapshot/`。

布局布线后 LUT 19410/20800（93.32%）、FF 22996/41600、BRAM36 等效 36/50（72%）、DSP 49/90。预处理模块综合层级为 321 LUT、496 FF、2 BRAM36、0 DSP；层级数字是综合值，不是布局布线后的单模块占用。全局 WNS +0.064 ns、WHS +0.015 ns，TNS/THS=0；100 MHz 核 WNS +0.601 ns。DRC 无 Error，USB T 释放、总线偏斜和既定 CDC 检查通过，没有新增时序豁免。

四模式逐档、阈值极值、60 秒 Sobel 和非零降噪集成测试共 3603 帧，加三档画质/启停/自动补光 690 帧，共 **4293 帧严格独立 JPEG 解码通过**。Sobel 阈值 8、降噪关闭连续 60 秒 1800 帧，最长间隔 33.33116 ms。全部测试零 FIFO 溢出、零失败描述符，约 30.002 fps。

4×2、16×8、1920×8 的独立整帧参考逐像素验证通过，包含四模式、阈值极值、正负梯度、反射边界、随机反压、帧内设置修改和 abort。共用窗口修改后，原稳健降噪和 1920×1080 RAW 整帧回归通过；按键、LED、三档量化表、连续启停及 kind 8 状态快照仿真通过，旧传输仍匹配六个 JPEG 金样。主机 103 项测试通过。

真实 Tk 窗口经按钮切换彩色→灰度→二值化→Sobel→彩色，测试任意亮度/边缘阈值、非法值拒绝、暂停显示时继续收帧、两次 PC 停止和再次开启。共收到 337 帧、显示 218 帧，编码失败和重连为 0，两个线程正常退出。本轮未重新人工按实体键或验证 LED 外观，保留原用户确认。
